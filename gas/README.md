# 銀松苑 機能訓練記録アプリ(GAS + スプレッドシート版)

- **データベース**: Google スプレッドシート(8シート)
- **Webアプリ**: Google Apps Script(HtmlService)
- 画面・デザインは `design_handoff_kinoukunren_app` のハンドオフを再現

## ファイル構成

| ファイル | 内容 |
|----------|------|
| `Code.gs` | サーバー側。doGet / API関数 / シート読み書き / setup() |
| `Index.html` | HTMLの外枠(フォント読込・CDN読込) |
| `Styles.html` | CSS(デザイントークン一式) |
| `Client.html` | 画面SPA(QR読取、利用者記録、評価、グラフ、連絡帳、CSV) |
| `appsscript.json` | マニフェスト(タイムゾーン・公開設定) |

## セットアップ手順(コピペで約5分)

1. **スプレッドシートを新規作成**(drive.google.com → 新規 → スプレッドシート)。
   名前は任意(例: 機能訓練記録DB)
2. メニュー **拡張機能 → Apps Script** を開く
3. エディタで以下を作成し、このフォルダの同名ファイルの中身を貼り付け:
   - `コード.gs`(既存)→ `Code.gs` の内容に置き換え
   - **+ → HTML** で `Index`・`Styles`・`Client` の3ファイルを作成し、それぞれ貼り付け
   - 歯車(プロジェクトの設定)→「appsscript.json をエディタで表示」を ON →
     `appsscript.json` の内容に置き換え
4. エディタ上部の関数選択で **`setup`** を選び **実行**(初回は権限承認が出ます)
   → 利用者・種目・来苑/帰苑・バイタル・訓練・脳トレ・評価・取消の各シートが作成されます。
   動作確認用データも必要な場合だけ `setupWithDemoData` を実行します
5. **デプロイ → 新しいデプロイ → 種類: ウェブアプリ**
   - 実行ユーザー: **自分**
   - アクセスできるユーザー: **同じ組織内(ginshoen.com)の全員**
     ※ タブレットでログインさせない運用なら「全員(匿名含む)」も可(URL を知っていれば誰でも記録可能になる点に注意)
6. 発行された **ウェブアプリURL** をスマホ/タブレット/PCで開く

## 職員ログインと権限

- アプリを開くと **職員ログイン**画面になります。自分の名前を選び、PIN(4〜8桁)を入力します
- 権限は2種類
  - **現場職員**: 受付(QRスキャン)・バイタル/機能訓練の記録・利用者情報の閲覧のみ
  - **管理者**: 上記に加えて管理画面(利用者管理・職員管理・連絡帳・月次レポートなど)
- 職員の追加・権限変更・PIN再設定は 管理画面 →「職員管理」から行います
- PINはハッシュ化して保存され、シートには平文が残りません。忘れた場合は管理者が再設定します
- ログインは12時間有効です。共有端末では作業後に「ログアウト」してください
- すべての記録に**記録者(職員名)**が残ります

### 初回の設定

1. Apps Script エディタで **`setup()` を実行**すると、職員マスタに「管理者」アカウントが1件だけ作成されます
2. 実行ログ(表示 → ログ)に **初期PIN(6桁のランダム値)** が一度だけ出るので控えます
3. 氏名「管理者」+ そのPINでログインし、**「職員管理」から自分の氏名・PINに変更**してください
4. 続けて職員を登録します(現場職員は権限「現場職員」を選択)

### セキュリティ上の注意

- PINは推測されやすい並び(0000・1234 など)を登録できません
- PINを5回続けて間違えるとその職員は15分ロックされます(以降は失敗のたびに倍増)
- **端末を紛失した/PINが漏れたときは、管理者が「職員管理」でその職員のPINを変更**してください。
  変更した時点で、その職員の既存ログインはすべて無効になります
- PINはソルト付きでハッシュ化して保存され、スプレッドシートに平文は残りません

## 運用メモ

- **QRコード**: 管理画面 →「種目マスタ / QR発行」で利用者QRカードを表示し「印刷」。
  カードには **氏名・利用曜日・介護度** が印字されます(名刺サイズ)。利用者QR: `GSU:<ID>`
  受付でQRを読み取ると **顔写真と基本情報の本人確認画面** が表示されます(30秒で受付へ自動復帰)。
  訓練機器のQRは廃止しました。機能訓練の記録では、画面の種目一覧から実施したものを選びます
  (個人別の「予定種目」設定は廃止し、全種目から選択する方式です)
- **顔写真**: 管理画面 →「利用者管理」→ 編集 →「📷 顔写真を選ぶ」。
  端末内で約320px四方のJPEGに自動縮小してからスプレッドシート(利用者マスタ「顔写真」列)へ保存されるため、
  Google ドライブ等の追加設定は不要です
- **マスタ管理**: 利用者・種目の追加/変更はスプレッドシートの
  「利用者マスタ」「種目マスタ」シートを直接編集(列の意味はヘッダー行の通り。
  選択肢はカンマ区切り、QRコードは `GSU:xxx` / `GSE:xxx` 形式。顔写真列は直接編集しない)
- **記録の確認**: すべての記録はシートに1行ずつ追記されるので、
  スプレッドシート側でも自由に集計・バックアップ可能
- **利用者基本情報**: 管理画面 →「利用者管理」で、個人目標・既往歴・運動禁止事項を登録
- **来苑/帰苑**: 「本日の記録一覧」で帰苑時刻と施設送迎/ご家族送迎を登録
- **評価記録**: 利用者詳細から脳トレ、体力測定、HDS-R、MMSEを登録
- **連絡帳**: 管理画面 →「連絡帳 作成・印刷」。当日の訓練・バイタルから文章を自動作成し、写真を追加してA4横1ページで印刷
- **アラート閾値**: `Code.gs` の `evaluateVitalAlerts_` と
  `Client.html` の `evaluateVitalAlerts`(同一ロジック)を両方修正
- **デモデータの削除**: チェックイン/バイタル/訓練記録/脳トレ記録/評価記録シートの2行目以降を削除
  (マスタ2シートは残す)

## カメラQR読取について

- トップレベル配信では `BarcodeDetector` API(Android Chrome 等)+ jsQR フォールバックを試行
- **GAS のウェブアプリは iframe 配信のため、Safari/Chromeともライブカメラが安定しません**。
  現在は撮影ボタンを常時表示し、写真から `jsQR` で読み取る方式を標準フォールバックにしています。
  ライブ読取を確実にしたい場合は、React 版(`kinoukunren-app`)を独立したHTTPSサイトとして利用してください。

## ローカルプレビュー

GAS にデプロイせずに見た目・挙動を確認する場合(データはブラウザ内モック):

```bash
python3 - <<'EOF'
import pathlib, re
index = pathlib.Path('Index.html').read_text()
combined = re.sub(r"<\?!=\s*include\('(\w+)'\);?\s*\?>",
                  lambda m: pathlib.Path(m.group(1) + '.html').read_text(), index)
pathlib.Path('preview.html').write_text(combined)
EOF
python3 -m http.server 8123   # → http://localhost:8123/preview.html
```
